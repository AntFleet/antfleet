## Why these two together

Both features feed the same north-star goal — receipt density on `/receipts` — but
from opposite sides:

- **Slice A** removes the human round-trip blocking *incoming* partners from
  producing public receipts. Every onboarded partner today must email
  `agent@antfleet.dev` or have the operator run
  `apps/web/scripts/enable-public-receipts.ts` before their closed findings
  reach `/receipts`. A signed link in the Onboarder's first-review summary
  flips the flag with one click. Compounds receipt corpus on autopilot.

- **Slice B** captures receipts from *outgoing* contributions —
  PRs opened by `antfleet-ops` on third-party repos (currently
  `Liquid-Protocol-Ops/agent-autonomopoly` #3 and #4). The sweep currently
  has no way to see those PRs merge because AntFleet's App isn't installed
  on those repos. A cross-repo receipt is the highest-trust artifact we
  can produce — "AntFleet flagged a bug on a repo it doesn't own, and the
  owner merged the fix at SHA X."

Ship A first (smaller, lower-risk, immediate compounding). Ship B second.

## Codebase reality check

Read these before reviewing the plan:

### R1 — Onboarder welcome prompt asks for email opt-in today

[apps/web/lib/onboarder.ts:177](apps/web/lib/onboarder.ts) instructs the agent
to write: "ask the maintainer to reply on this issue or email
agent@antfleet.dev if they want to opt in". That string is generated by the

out of generated text.

### R2 — `onboarding_events` already has the event vocabulary

[apps/web/db/schema.ts](apps/web/db/schema.ts) lists
`public_receipts_enabled` and `public_receipts_disabled` as valid event
types. The audit shape is already in place — the toggle just needs to emit
these events. No schema migration for the audit row itself; Slice A's only
migration is the opt-in-token table (or none if we go stateless).

### R3 — Sweep is App-installation-scoped

[apps/web/db/queries.ts:165](apps/web/db/queries.ts) `loadSweepWork()` joins
`finding_status` → `reviews`. There is no `reviews` row for a PR opened on
a repo where AntFleet's App is not installed. Slice B therefore needs an
independent data path (new table + new sweep entry point); it cannot piggy-
back on `finding_status`.

### R4 — Existing outgoing-PR record is markdown, not data

[docs/demos/upstream-fix-prs.md](docs/demos/upstream-fix-prs.md) has hand-
filled rows for the two open upstream PRs with "Closing SHA (if merged):
_fill later_". Slice B migrates that file into a real table and seeds it
with the two existing PRs. The markdown file can stay as a human-readable
mirror but isn't load-bearing after this slice.

### R5 — `antfleet-ops` is a real GitHub user, not the bot

The PRs on upstream repos are authored by the `antfleet-ops` user account
(the operator's bot identity). The `antfleet[bot]` GitHub App is what posts
comments inside our own org. Don't confuse them — outgoing PR detection
keys on the `antfleet-ops` author, not on the App.

## Slice A — Self-serve public-receipts toggle (signed link)

### Scope

The Onboarder's first-review summary comment includes a one-click signed
link of the form:

```
https://www.antfleet.dev/api/opt-in?t=<token>
```

Clicking it flips `reviews.public_receipt = true` for every review row
matching `(owner, repo)` for that install, emits a
`public_receipts_enabled` onboarding event, and renders a small
confirmation page. The same link allows reversing the opt-in by appending
`&action=disable`.

### Decisions to lock before coding

1. **Token shape: stateless HMAC, no DB table.**
   - Payload: `{installationId, owner, repo, exp}` (exp = now + 30 days)
   - Sign with `OPTIN_HMAC_SECRET` (new env var, base64 of 32 random bytes)
   - Encode as `base64url(json) + "." + base64url(hmac)`
   - Verify on click; reject if HMAC mismatch or expired
   - Rationale: no table, no cleanup, no PII at rest. Replay within 30
     days is fine — flipping the flag idempotently is a no-op.

2. **Link placement: first-review summary comment, not welcome issue.**
   - Welcome runs before any review exists; the maintainer has no signal
     yet on whether the bot is useful. Linking from first-review summary
     means the maintainer has just seen real findings at the moment of
     opt-in. Higher conversion, lower regret.
   - Welcome issue should keep a fallback line ("public receipts off by
     default — when your first PR is reviewed, you'll get a one-click
     opt-in link in the summary") but drop the `agent@antfleet.dev` ask
     entirely.

3. **Idempotency: clicking twice is a no-op, not an error.**
   - If `public_receipt` is already true and `action=enable`: render "already
     enabled" page, emit no duplicate event.
   - If `action=disable` is clicked: flip flag back, emit
     `public_receipts_disabled`.

### Files to add

- `apps/web/lib/optin-token.ts` — `signToken({installationId, owner, repo})`
  + `verifyToken(t)` returning `{installationId, owner, repo} | null`.
  Pure, deterministic, fully unit-tested in `optin-token.test.ts`.
- `apps/web/app/api/opt-in/route.ts` — GET handler. Verify token, flip
  flag, emit onboarding event, return HTML response. No POST.
- `apps/web/app/api/opt-in/route.test.ts` — integration test against test
  DB.

### Files to modify

  - `welcomePrompt` (line 152): drop the email-opt-in sentence. Replace

  - `firstReviewSummaryPrompt` (line 186): take a new arg

  - `runFirstReviewSummary` (the function that calls
    `firstReviewSummaryPrompt`): generate the URL via `signToken` and pass

- [apps/web/app/policy/page.tsx](apps/web/app/policy/page.tsx): update the
  "Public vs private" section. Email is now a fallback, not the primary path.

- `.env.example` and Vercel production env: add `OPTIN_HMAC_SECRET`.

## Slice B — Cross-repo receipt linkage

### Scope

Track outgoing PRs opened by `antfleet-ops` on third-party repos.
Periodically poll their merge state. On merge, surface the PR + closure
SHA on `/receipts` as a distinct "cross-repo receipt" class.

### Decisions to lock before coding

1. **New table, not extension of `reviews`.** Outgoing PRs don't have a
   `reviews` row (no App install on the upstream repo). Adding nullable
   `outgoing_*` columns to `reviews` would pollute the dominant query
   surface. Separate table is cheaper and clearer.

2. **Manual seeding initially, webhook automation deferred.** Phase 2
   doesn't justify building outgoing-PR auto-detection. Operator runs a
   script after opening each cross-repo PR. v1.5 can auto-detect via
   `antfleet-ops`'s GitHub event feed.

3. **Surface design: separate visual class on `/receipts`.** A cross-repo
   receipt has different metadata (upstream owner/repo, source-finding
   link to *our* repo) than a same-repo closure receipt. Render as its own
   row variant with explicit "AntFleet → `<upstream>`" prefix. Don't mix
   visually with same-repo receipts; the trust claim is meaningfully
   different.

### Files to add

- `apps/web/db/migrations/0007_*.sql` — new table:

  ```sql
  CREATE TABLE outgoing_prs (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    source_finding_id text NOT NULL,        -- references finding_status.finding_id
    upstream_owner    text NOT NULL,
    upstream_repo     text NOT NULL,
    upstream_pr_number integer NOT NULL,
    branch_on_fork    text NOT NULL,
    opened_at         timestamptz NOT NULL DEFAULT now(),
    status            text NOT NULL DEFAULT 'open',  -- open | merged | closed
    merged_at         timestamptz,
    merge_sha         text,
    last_polled_at    timestamptz,
    UNIQUE (upstream_owner, upstream_repo, upstream_pr_number)
  );
  ```

  No FK on `source_finding_id` — finding rows can be superseded but the
  outgoing PR's provenance should survive that. App-level constraint is
  enough.

- `apps/web/db/schema.ts`: matching Drizzle `outgoingPrs` table.
- `apps/web/lib/outgoing-prs.ts` — `pollOutgoingPrs(deps)` orchestrator:
  - Load all `outgoing_prs` with `status = 'open'` and
    `(last_polled_at IS NULL OR last_polled_at < now() - 1h)`
  - For each, call GitHub REST API `GET /repos/{owner}/{repo}/pulls/{n}`
    using `antfleet-ops`'s personal access token (new env
    `ANTFLEET_OPS_GH_TOKEN`, read-only `repo:status` scope — no
    write needed since the PR is already open and we only read state)
  - If `merged_at` is non-null: set status=merged, merge_sha, merged_at,
    log `outgoing_pr.merged` event
  - Else if `state == "closed"` and `merged_at` is null: set
    status=closed (declined), log `outgoing_pr.declined`
  - Update `last_polled_at` either way
- `apps/web/lib/outgoing-prs.test.ts`
- `apps/web/scripts/seed-outgoing-pr.ts` — operator script. Args:
  `<source-finding-id> <upstream-owner> <upstream-repo> <upstream-pr> <branch>`.
  Inserts a row. Idempotent on (owner, repo, pr).
- `apps/web/lib/receipts.ts` — extend with `loadCrossRepoReceipts()` that
  returns merged outgoing PRs, joined to the source finding for
  display metadata.

### Files to modify

- [apps/web/app/api/cron/sweep/route.ts](apps/web/app/api/cron/sweep/route.ts):
  add a `pollOutgoingPrs()` call after the existing sweep. Independent of
  finding_status reconciliation — if one fails the other still runs.
- [apps/web/app/receipts/page.tsx](apps/web/app/receipts/page.tsx): add a

  `cross-repo` so subscribers can filter.
- [docs/demos/upstream-fix-prs.md](docs/demos/upstream-fix-prs.md): add a
  note at the top — "monitoring is now automated via the

- `.env.example`: add `ANTFLEET_OPS_GH_TOKEN`.

## Things to avoid

- **Do not store the OPTIN_HMAC_SECRET in the repo.** Vercel env only.
- **Do not log the signed token** — it's a bearer credential for 30 days.
  Log a hash of it (`sha256(token).slice(0,12)`) if you need correlation.
- **Do not break existing email opt-in path.** `enable-public-receipts.ts`
  must still work — operator fallback for maintainers who lose the comment.
- **Do not let `pollOutgoingPrs` fail the cron.** Wrap in try/catch; log
  error, continue to the next sweep step. Same pattern as existing
  `runSweep`.
- **Do not surface declined upstream PRs on /receipts.** Honest-report
  principle: a closed-without-merge PR is not a receipt.
- **Do not poll upstream PRs more than once an hour.** GitHub rate
  limits are forgiving but the operator's PAT is the same one used for
  manual `gh` work — exhausting it disrupts the human.
- **Do not commit the `ANTFLEET_OPS_GH_TOKEN` to `.env.local`** without
  also marking it private. The token has write scope on the upstream
  forks even if we only need read here — issue a fresh read-only token
  for production.
